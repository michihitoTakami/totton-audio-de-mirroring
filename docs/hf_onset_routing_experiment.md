# HF-onset routing class — 実験記録（不採用、2026-09-04）

打撃時の高域を取り戻すため、`gentle` の代わりにフラットな `mid` を使う routing クラスを
試作し、**不採用**とした記録です。実装は残していません（この文書が唯一の記録です）。

推奨は **run16**（`v5b_sharp1023_midflat70`、`focused_gentle_fraction 0.3`、gate spec 7）の
まま変わっていません。

## 動機

`gentle` は 15 kHz で `-4.3 dB`、20 kHz で `-10 dB` 落ちる Bessel6@20k です。したがって
打撃の瞬間に `gentle` へ寄るほど、**まさに打撃が存在する帯域が削れます**。一方、矩形波や
DC step のエッジでは失うものがありません。この2つは物理的に別のケースなのに、run16 の
prior は同じ「包絡onset経路」で扱い、どちらも `gentle` 単独へ送っています。

run16 のリリース記録は、この床を `-3.2 dB`（ハイハット 16–20 kHz、Sharp比）と記録し、
「下げるには onset 経路の保護先を変える別の knob が必要」としていました。本実験はその knob です。

### 実験前に測った上限

`gentle` 配分を下げたときに取れる高域を、prior 単体（学習ヘッドをゼロ化）で掃引しました。
`hf_onset_threshold 0.8`、all-sharp レンダリング基準:

| HF-onset gentle 配分 | hi-hat 16–20 kHz | among-us 16–20 kHz |
|---|---|---|
| 1.00（= run16 相当） | −2.72 dB | −4.33 dB |
| 0.30 | −1.81（0.90 dB回復） | −1.77（2.56 dB回復） |
| 0.00（理論上限） | **−1.46（1.25 dB）** | **−0.85（3.48 dB）** |

**上限は素材次第で 1.25〜3.48 dB。** 12–16 kHz も並行して改善します。

## 設計

判別すべき2クラスは「広帯域HF onset」（打撃）と「低域波形中のエッジ」（矩形・DC step）です。
既存の prior 3項（`level_risk` / `crest_risk` / `sustained`）では分離できませんでした。
導関数 crest では **2 kHz矩形(3.32) がホワイトノイズ(4.17) より低く**、閾値では分けられません。

採用した指標は **onset 後のHFエネルギー持続**です。矩形エッジの直後は DC なので HF はほぼ
ゼロ、打撃は密な HF が続く、という物理差を直接使います。具体的には slew index
（導関数RMS / 波形RMS、純音なら `2πf/fs`）の**前方max**を取り、シグモイドに通します。

前方**平均**では失敗しました。prior の risk ピークは打撃の 3.3〜25 ms 手前にあるため、
短い窓では打撃に届かず、合成ハイハットで指標が 0.001 になります。look-ahead を覆う
20フレーム（約29 ms）の前方 max にして解決しました。

分離は良好でした（`level_risk` が立つケースのみ）:

| 信号 | 指標値 | 期待 |
|---|---|---|
| kick 80 Hz onset | 0.129 | 閉じる |
| DC step | 0.276 | 閉じる（拘束条件） |
| glitch 打撃 | 0.752 | 開く |
| 実ハイハット | 1.004 | 開く |

閾値 0.8 は、`tone_burst_3700hz_held` をクラス外に保って G7 added-HF の merit pass を
守るために選びました。0.6 では added HF が `+1.3 → +7.3 dB` と閾値 `+3 dB` を越え、
negligible-image 免除条項に依存する形に落ちます。

## 結果 — 3回の試行

いずれも run16 から 20 epochs / lr 1e-4 で controller を fine-tune（bank 変更なし）、
3 seed × 両 rate family、spec 7 で CPU と strict-FP32 CUDA を評価しました。
採用基準は run16 と同じ「3 seed × 両系列で G1〜G9 全通過」です。

| 試行 | 44.1k gates | 48k gates | 1 kHz矩形 max mid | ハイハット 16–20 kHz |
|---|---|---|---|---|
| **run16**（基準） | — | — | 0.0000 | −2.87 dB |
| 1. 制約なし | 3/3 | **0/3 FAIL** | 0.134〜0.379 | **−1.87〜−2.05**（0.8〜1.0 dB回復） |
| 2. ceiling損失（未ゲート） | 2/3 | 3/3 | 0.003〜0.006 | −3.29〜−3.75（**0.4〜0.9 dB悪化**） |
| 3. ceiling損失（ゲート付） | **3/3** | **3/3** | 0.0006〜0.0060 | −2.40 / −2.81 / −2.74 |

### 試行1 — prior は正しく、NN が壊す

推論時だけ（学習なしで）prior を差し替えた段階では、すべてが期待どおりでした。全 probe で
G1〜G9 通過、リンギングgateの使用率は4桁一致で不変、イメージ帯は 3.4 dB 改善
（`-88.2 → -91.6 dB`）。矩形・DC step・孤立impulse は**ビット一致**でした。

学習すると 48 kHz が 3 seed とも `G2_hf_ringing` で落ちました（`square_1000hz` plateau_rms が
run16 の 35.4% に対し 97.6 / 246.3 / 317.4%）。44.1 kHz は通りましたが 3 seed 中 2 つで
G2 使用率がほぼ倍（40.9% → 70.3% / 76.1%）でした。

原因は測定で特定できました。1 kHz矩形での `mid` の重みは:

| | 学習済み max mid | **prior単体 max mid** |
|---|---|---|
| run16 | 0.0000 | 0.0000 |
| 試行1 の3 seed | 0.1340 / 0.2977 / 0.3786 | **すべて 0.0000** |

**prior は完璧に閉じています**（周期矩形は `level_risk ≈ 0` なのでブランチが開かない）。
壊しているのは学習済み NN で、「onset では mid へ渡す」を**矩形エッジへ過剰般化**していました。
`mid` の plateau リップルは Bessel の 26〜38 倍なので、13〜38% 混ざるだけで G2 の余裕が消えます。

損失側は矩形エッジに gentle 単独を要求していたので、教え方の不足ではなく汎化の限界です。

### 試行2 — 制約が強すぎ、かつ実装バグ

`stationary_sharp_floor`（重み1000）と同型の hinge を追加しました。あれは「1 seed が定常
ノイズに gentle を漏らして G3 を落とす」という**同種の漏れ**を解決した前例です。

48 kHz は直りました（漏れ 0.134〜0.379 → 0.0030〜0.0065）。しかし**高域が run16 より悪化**
しました。学習データの各クラスで hinge が与えていた mid 許容量を測ると:

| クラス | 指標値 | mid 許容 | |
|---|---|---|---|
| clustered_impacts / impact_stream | 0.774 / 0.742 | 0.562 / 0.540 | 許容（正） |
| **isolated_click** | 0.432 | **0.323** | ← **バグ** |
| square_wave | 0.108 | 0.096 | 抑制（正） |
| damped_string / string_riff | 0.031 / 0.014 | 0.042 / 0.030 | 抑制（正） |

孤立click は *focused* クラスで、`focused_gentle_fraction 0.3` により **mid 0.7 が正しい**値です。
ところが hinge は生の `edge_mask` を使い、`prototype_routing_loss` が
`gentle_mask = frame_edges × (1 − focused_frames)` で除外している focused フレームを
除外していませんでした。**run16 が依存している孤立impulseの mid 0.7 を押し下げていた**わけです。

### 試行3 — ゲート付き。gate は通り、効果は消えた

2点直しました。focused フレームの除外（正しさ）と、eligibility を
`gentle_share ≥ 0.9` の**二値ゲート**化（prior が mid に質量を与えるフレームでは hinge を
厳密にゼロにする）です。実クラスの分布は境界の両側に明確に離れています
（打撃系 0.458〜0.697 / 対象側 0.924〜0.990）。

当初は 0.8→0.9 の滑らかな ramp にしましたが、**数値的な脆さ**で二値に変えました。
eligibility が厳密な 0 でなく 3.58e-07 になると、`sum(hinge) / sum(eligible)` がその微小値で
割って満額の損失を復活させます。前例の `stationary_sharp_floor_loss` は eligibility が
二値マスクの積なのでこの問題がありません。

結果、**gate は 6/6 全通過、漏れも許容の3分の1以下**になりましたが、**回復量が
0.47 / 0.06 / 0.13 dB** に落ちました。3 seed 中 2 つは run16 と実質同一で、最良 seed でも
目標 0.9 dB の半分、上限 1.25 dB の 3 分の 1 強です。

イメージ帯の改善は残りました（hi-hat `-81.0 → -83.3 dB`、among-us `-78.3 → -83.0 dB`）。

## 不採用の理由

**トレードオフが構造的でした。** 3 試行がその両端と中間を押さえています。gate を通すために
必要な制約が、そのまま効果を削る制約です。NN が打撃で mid を使えるだけ自由でなければ
効果が出ず、その自由がそのまま矩形エッジへの漏れになります。漏れを潰したら効果も潰れました。

**得るものが払うものに見合いません。** 得られるのは高域 0.06〜0.47 dB（seed依存、最良でも
16 kHz 超で 0.47 dB）とイメージ帯 2.3〜4.7 dB。払うのは routing クラス1つ、prior 定数4つ、
損失項1つ、そして新しい失敗面です。実際この実験だけで実装バグ1件と数値的脆さ1件を踏みました。

run16 の ABX では、これより**大きい差**（Sharp との 2.3〜2.9 dB のギャップ全体）が識別不能
でした。イメージ帯の改善は契約上（no-added-HF）正当ですが、`-81 dB` から `-83 dB` への
改善であり、G3 / G7 の余裕は元々十分あります。

`AGENTS.md` の「候補を通すために gate を弱めない」に従い、G2 の調整は行っていません。

## この実験が確定させたこと

**prior は 3 試行すべてで正しく振る舞い（1 kHz矩形で max mid = 0.0000）、壊すのは常に
NN 側でした。** 無制限の NN 残差が律速である、という以前からの観察を、3 通りの制約設定で
裏付けたことになります。

これは別の観察と整合します。run16 の controller と、その prior 単体の全変動距離（TVD）は、
prior が正しいクラスでは 0.001〜0.029 とほぼゼロですが、prior が外すクラス（2 kHz矩形）では
0.9995、つまり NN が判断を丸ごと置き換えています。NN は prior が苦手なところを救う一方で、
prior が正しいところを壊す力も同じだけ持っています。

したがって投資方向は「新しいクラスを prior に足す」ではなく、**prior の特徴量を強化して
NN 残差を縮め、最終的に残差を縛る**方向です。残差を縛る試みは、square クラスで NN が
prior を完全に上書きしている（TVD 0.9995）ため、グローバルなクランプでは行えません。

## 試していない選択肢

**指標を controller の入力チャンネルとして与える。** 試行3で効果が消えた原因が汎化ではなく
**容量**（指標が「slew index の 29 ms 前方 max」という長距離の非線形量で、controller の
4 入力ch にそれを表すものが無い）なら、近似させるのをやめて読ませれば効く可能性があります。
`controller_feature_mode` を1つ増やす形になり、第1層の形が変わるため run16 からの
warm start が効かず、50 epochs 級の学習 campaign（約1.4時間）になります。

期待値は依然 1 dB 未満なので着手していません。再検討するなら、まず上限（1.25〜3.48 dB）の
うちどこまでが可聴かを ABX で確かめる方が順序として妥当です。
